# Cluster 面板设计说明（1.2.0）

这份文件记录的是**决策来源**，方便以后改版时知道哪些是刻意为之、哪些只是巧合。
所有借鉴都只取结构与原则，未复制任何源码。两个参照项目都是 MIT 许可。

## 参照了什么

### Tabler（https://github.com/tabler/tabler，MIT）

拿了它的页面骨架：

- `page-header → page-body` 的分段：顶栏和内容区用细分割线切开，内容区成为唯一的视觉舞台。
- **`row-deck`（同一行卡片等高）**：一排节点卡底边对齐。不等高时行列底线参差，
  整屏立刻显得没排过版。
- **卡片顶部的 3px 状态条**：栅格里不需要读文字，扫一眼颜色就知道哪台有问题；
  而且它不改卡片底色，暗色模式下不会变成一片荧光。
- 中性色分阶与"极轻阴影"：卡片默认几乎无阴影，靠间距和描边分隔，暗色下不堆阴影。

### Beszel（https://github.com/henrygd/beszel，MIT）

拿了它的监控语汇：

- **每个指标固定一个色相**（CPU 恒蓝、内存恒紫），跨节点不变。
  按序列顺序取色会让 A 节点第一条是蓝、B 节点第二条是橙，整屏就花了。
  因此高负载**不把整条染色**，只把数值标红 —— 否则同一条图里会出现第三种颜色。
- 状态用「色点 + 文字」，不给整卡染色。整卡 `bg-danger` 在 20 台里 3 台红时就全屏报废。
- 只有四个语义色：在线 / 降级 / 离线 / 未知。**未知用灰，不用红** —— 未知不是故障。
- 等宽数字（`tabular-nums`）：数值每秒跳动，比例数字会让整列左右抖动。

### 明确没有取的

- **Netdata 的 UI 资产是闭源（NCUL1）**，只采纳了它文档里的一句设计理念——
  "别让页面只有一个红绿灯"，即每个异常必须回答「为什么」。没有使用任何资产或 CSS。

## 定下来的结构

```
顶栏（品牌 + 一句话概览 + 刷新）
标签页（总览 / 工作区同步）
内容区（唯一滚动容器）
  1. 集群实时状态带   ← 本页重心：一句话结论 + 逐个节点状态
  2. 指标条（5 格）   ← 降一档，不与状态带争注意力
  3. 工作台
       主列：节点运行状况（节点卡 + 资源条）
       窄栏：任务队列 / 同步状态
Router 常驻底栏（贴视口底，不覆盖内容区）
```

为什么这样分：之前是"一叠等宽白卡自上而下"，每块权重相同，读起来没有入口。
现在第一眼落在状态带的结论句上，第二眼看节点行，第三眼才看数值与明细。

## 状态编码（三层，各管一件事）

| 层 | 用在哪 | 形态 |
| --- | --- | --- |
| 结论句 + 左侧色条 | 状态带 | 一句话说清「正常 / N 台离线 / N 台高负载」 |
| 色点 + 文字 | 节点行、卡片胶囊 | 在线 / 高负载 / 采样过期 / 能力异常 / 离线 |
| 3px 卡顶条 | 节点卡栅格 | 不读文字也能看出哪台有问题 |

**同一台机器在状态带和卡片里必须说同一句话。** 判定收敛到单一函数 `nodeCondition()`，
卡片和状态带都调它。之前两处各写一套，出现过「标题说高负载、卡片说在线」的自相矛盾。

阈值：采样超过 30 秒未更新 → 采样过期；CPU 或内存 ≥90% → 高负载；有下线能力 → 能力异常；
`alive:false` → 离线（最高优先级）。异常卡片右侧直接写出原因（如 `CPU 91% · 内存 86%`）。

## 配色

浅色以 `#f4f6fa` 托底、白卡浮起；主色 `#206bc4`；语义四色
`good #178a6b` / `warn #9a5c07` / `bad #d63939` / 中性灰。
暗色整体换一套（`#0f1822` 底 / `#182433` 卡），不是简单反色。

## 已知取舍

- 内容区外边距从 32px 收到 28px，换来右侧 316px 窄栏。窄栏让「任务 / 同步」这类
  次要但需要常看的信息有了固定位置，不再和主内容抢整行。
- 指标条数值从 30px 收到 26px：状态带已是重心，指标条若维持 30px 会与之争夺注意力。
- Router 从内容流中的卡片改为贴底常驻栏。它是随时可用的指令入口，不是页面内容；
  代价是底部常驻一条深色带，展开时最多占 42vh（日志区内部滚动），保证输入框不被挤出视口。
